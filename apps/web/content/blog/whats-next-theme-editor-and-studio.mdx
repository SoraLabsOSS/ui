Most posts here so far have been about this site. This one's about what's next — two projects I'm starting work on, and why they exist.

## A visual theme editor for Sora UI

Right now, customizing a Sora UI primitive means opening the file and editing Tailwind classes by hand. That's the whole point of the registry model — you own the source — but it also means there's no fast path to "just show me what this looks like in my brand colors" before you commit to editing anything.

I'm building a visual editor for that: pick a primitive, tweak colors, radii, and spacing tokens against a live preview, and export the result as CSS variables or Tailwind config you drop straight into your project. Think of it as the same idea behind tools like [tweakcn](https://tweakcn.com) — a theme customizer for the shadcn ecosystem — but scoped to Sora UI's tokens and motion-aware components.

It doesn't change the install flow. You still `npx shadcn add @soralabs/...` and get real source in your repo. The editor is just a faster way to land on a theme before you start hand-editing files.

## Sora Studio: landing pages, pro tier

The primitives and blocks in the docs stay free and open — that's not changing. Sora Studio is a separate thing: a paid line of complete landing page templates, built entirely on Sora UI primitives, for people who want a finished, polished page rather than a component catalog to assemble themselves.

The target is teams and freelancers shipping client landing pages who don't have time to compose a hero, pricing section, and scroll-driven feature showcase from scratch — but still want the motion quality Sora UI is built around, not a generic template that looks like every other one.

## Where things stand

Both are early — I don't have a ship date for either yet, and the scope of both will probably shift as I actually build them. What I do know: the theme editor comes first, since Sora Studio's templates will be styled through it. I'll post implementation notes here as pieces land, the same way the primitives get written up.

If you're using Sora UI and have a specific theming pain point — or a landing page section you keep rebuilding by hand — that's useful signal for what to prioritize first.

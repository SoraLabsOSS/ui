The Sora UI Roadmap outlines upcoming milestones, priority tiers, and animation engineering goals. Our architecture follows a phased rollout prioritizing **Base UI** first, followed by **Comprehensive RTL (Right-to-Left) Support** across all existing registries, expanding into **Agent-Native Semantic Composition Enrichment**, scaling the **Radix UI** suite, and growing into other headless libraries and multi-framework ecosystems.

<RoadmapTimeline />

## Prioritization Strategy

Our component development follows a structured roadmap designed to provide complete, production-ready animated primitives:

<Steps>
<Step>

### Phase 1: Base UI First (Current Focus)

[Base UI](https://base-ui.com) provides an unstyled, highly accessible component foundation designed for modern React. We are systematically building Motion-powered animated variants for all **13 core Base UI components**:

- **Button** (`/ui/base/button`) — Physics spring hover/tap scaling and comprehensive CVA variants. *(Completed)*
- **Checkbox** (`/ui/base/checkbox`) — Animated checkmark path morphing and elastic pop feedback. *(Completed)*
- **Dialog** (`/ui/base/dialog`) — Smooth backdrop blur with scale-in spring physics. *(Completed)*
- **Alert Dialog** (`/ui/base/alert-dialog`) — 3D perspective spring rotation, customizable sizes, and media slots. *(Completed)*
- **Accordion** (`/ui/base/accordion`) — Smooth layout-height morphing and spring chevron rotation. *(Completed)*
- **Context Menu** (`/ui/base/context-menu`) — Spring scale physics with cascaded submenu slide transitions. *(Completed)*
- **Dropdown Menu** (`/ui/base/dropdown-menu`) — Collision-aware floating popovers with spring scale physics and cascaded submenus. *(Completed)*
- **Tooltip** (`/ui/base/tooltip`) — Micro scale-fade tooltip with dynamic arrow position tracking. *(Completed)*
- **Switch** — Inertia stretch toggle with rubber-band physics. *(In Progress / Next)*
- **Progress** — Elastic bar fill with indeterminate shimmer and animated numeric ticker. *(Planned)*
- **Radio / Radio Group** — Shared `layoutId` gliding active indicator. *(Planned)*
- **Select** — Floating dropdown with active pill glide and keyboard navigation. *(Planned)*
- **Tabs** — Sliding background indicator pill and cross-fading tab panels. *(Planned)*
- **Toast** — Stacked notification queue with swipe-to-dismiss gesture physics. *(Planned)*
- **Toggle Group** — Multi-select animated bounding boxes. *(Planned)*

</Step>
<Step>

### Phase 2: Comprehensive RTL Support & Existing Registry Retrofit (Next Priority)

Comprehensive Right-to-Left (RTL) internationalization is our immediate next focus. We are prioritizing retrofitting all existing components in the Sora UI registry to provide first-class native support for Arabic, Hebrew, Persian, and Urdu locales:

- **Existing Registry Retrofitting (Top Priority)**: Retrofitting all active components across the Base UI suite, Radix UI suite, and unstyled Motion Primitives with native bidirectional behavior.
- **CSS Logical Properties**: Full migration to Tailwind CSS logical utilities (`start`, `end`, `ps`, `pe`, `ms`, `me`, `border-s`, `border-e`, `inset-inline-*`) replacing physical left/right constraints.
- **Directional Motion Physics**: Automatic transform inversion for directional spring transitions (e.g. inverted horizontal sliding `x: -20` vs `x: 20`, drawer fling physics, and gesture dismissal).
- **Collision & Submenu Flipping**: Collision-aware popovers, context menus, and dropdown submenus cascading correctly to the left in RTL orientation.
- **Visual & Layout Indicators**: Reversing chevron rotations, sliding active background pills (`layoutId`), and timeline progress tracks.

</Step>
<Step>

### Phase 3: Agent-Native UI & Semantic Composition Enrichment (Post-RTL Priority)

Following our RTL rollout, we are prioritizing transforming the UI registry content into a high-density, agent-grounded knowledge base. This equips AI coding assistants (via Sora MCP and agent tools) with deep semantic context rather than just raw JSX strings:

- **Structured Agent Frontmatter**: Enriching all active Base UI and Radix UI component MDX pages with machine-readable metadata (`intent`, `role`, `a11yConstraints`, `motionEngine`, `compositionRules`).
- **Multi-Primitive Composition Recipes**: Documenting explicit multi-component compositions (e.g., nesting Base UI Dialog + Form + Spring Button + Presence) so AI models can orchestrate layouts without hallucinations.
- **Base UI Integration Guardrails**: Concrete pattern documentation for LLMs (e.g. enforcing Base UI's `render={<Component />}` pattern over legacy Radix `asChild`, focus trap synchronization, and ESC handlers).
- **Published Registry Semantics**: Mirroring agent metadata into `registry-item.json.meta.agentMetadata` and published `public/r/*.json` artifacts so MCP can access it through component info without parsing JSX.
- **Composition Validation Surface**: Adding MCP composition validation for component names, registry dependencies, accessibility constraints, composition rules, and motion requirements.

**Status: Foundation complete.** Phase 3 now provides the semantic contract and MCP validation surface that agents can consume. It does not yet automatically plan a component tree, select recipes, generate files, or run deep runtime accessibility and motion audits.

The next automation milestone is:

- **Agent Composition Planner**: Convert a user prompt into an explicit component tree and dependency graph.
- **Recipe Selection**: Match the requested intent to compatible published composition recipes.
- **Code Generation Orchestration**: Install or compose registry items, generate project files, and preserve each component's guardrails.
- **Deep Validation**: Run type, accessibility, reduced-motion, focus lifecycle, and class-conflict checks on generated output.

</Step>
<Step>

### Phase 4: Radix UI Suite Expansion

Our Radix UI tier infuses [Radix Primitives](https://www.radix-ui.com/primitives) with Sora Motion spring dynamics and layout orchestration:

- **Completed**: Button, Checkbox, Dialog.
- **Upcoming & Redesign**: Bottom Sheet, Accordion, Alert Dialog, Context Menu, Dropdown Menu, Hover Card, Menubar, Navigation Menu, Popover, Select, Separator, Slider, Switch, Tabs, Toast, Tooltip.

</Step>
<Step>

### Phase 5: Other Headless UI Libraries (Future Planning)

To provide universal flexibility across different architecture requirements:

- **React Aria Components**: Adobe's accessibility primitives combined with Sora Motion spring physics.
- **Ark UI**: Zag.js state-machine driven components with universal animation presets.
- **Headless UI & Ariakit**: Clean adapters for Tailwind Headless UI and Ariakit.

</Step>
<Step>

### Phase 6: Cross-Platform & Ecosystem Expansion

- **Vue 3**: Official component ports using Motion for Vue.
- **Vanilla JavaScript**: Web components and framework-agnostic wrappers.

</Step>
</Steps>

## MotionScore™ Performance Auditing

Every component in the Sora UI registry is engineered for 60/120 FPS performance and benchmarked across four key animation categories:

| Tier | Render Pipeline Work | Animation Characteristics | Performance Standard |
| :--- | :--- | :--- | :--- |
| **Tier S** | **Compositor Only** | Runs entirely on the GPU compositor thread (`transform`, `opacity`). | Zero main-thread interruption, 120 FPS capable, full reduced-motion branch. |
| **Tier A** | **Main-Thread Composited** | Changes composited values from the main thread with micro-orchestrations. | Zero layout shifts, keyboard and focus synchronized. |
| **Tier B** | **Measured Animation** | Requires upfront DOM measurements (e.g. FLIP layout morphing, bounds calculation). | Smooth FLIP transitions without layout thrashing. |
| **Tier C** | **Paint Triggering** | Triggers paint operations (colors, shadows, SVG paths, background transitions). | Non-intrusive, isolated repaints. |
| **Tier D / F** | **Layout & Thrashing** | Interleaved DOM reads/writes or layout recalculations (`width`, `height`, `top/left`). | **0% Zero-Tolerance**: Strictly eliminated in Sora UI. |

### Running Local Audits with MotionScore CLI

You can audit any component or page locally in your development environment for free using the [MotionScore CLI](https://score.motion.dev/docs/cli). The `--no-upload` flag runs a headless Chromium browser locally on your machine with **unlimited, unmetered audits**:

<Steps>
<Step>

### Start Dev Server & Run Audit

Run an unmetered local audit on your active development server without consuming cloud credits:

<CodeTabs
  codes={{
    bun: `bun run audit:motion`,
    npx: `npx motionscore http://localhost:3000/ui/base/button --no-upload`,
    pnpm: `pnpm dlx motionscore http://localhost:3000/ui/base/button --no-upload`,
  }}
/>

</Step>
<Step>

### Test Viewport Formats

Audit specific viewport layouts to catch responsive animation regressions:

- **Mobile Viewport Only**:
  ```bash
  npx motionscore http://localhost:3000/ui/base/checkbox --mobile-only --no-upload
  ```
- **Desktop Viewport Only**:
  ```bash
  npx motionscore http://localhost:3000/ui/base/dialog --desktop-only --no-upload
  ```

</Step>
<Step>

### Export Report Summary

Export compact JSON findings for automated assertions or CI/CD pipelines:

```bash
npx motionscore http://localhost:3000/ui --summary audit-report.json --no-upload
```

</Step>
<Step>

### Review the 4 Audit Pillars

The audit evaluates your component across four core render pipeline signals:

1. **Animation Properties**: Identifies properties triggering layout reflows (`width`, `height`, `top`, `left`) vs GPU-accelerated transforms.
2. **Scroll Performance**: Evaluates scroll-linked transforms and trigger synchronization.
3. **DOM & Style Thrashing**: Detects interleaved reads and writes causing forced reflows.
4. **GPU Texture & Memory**: Measures VRAM consumption and compositor layer count.

</Step>
</Steps>

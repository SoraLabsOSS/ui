## Origins

Sora UI started as a fork of [Animate UI](https://animate-ui.com) by [@imskyleen](https://x.com/imskyleen). The initial codebase, registry conventions, and copy-paste distribution model came from that project.

Since then, the architecture, registry system, component APIs, and motion primitives have been substantially redesigned. Some patterns and abstractions still trace back to the original codebase.

## Direction

Sora UI is built around a dual-comprehension philosophy: UI components whose behavior, constraints, composition, and metadata are understandable by both humans and AI agents. It pairs an open, copy-paste registry architecture with structured metadata exposed through an [MCP server](/docs/mcp), alongside a component roadmap centered on motion-first, composable primitives.

What's different from upstream:

- **Built for humans and AI** — an MCP server delivering rich metadata (intent, accessibility constraints, motion semantics, and composition rules) so AI assistants reason accurately about components
- **Three-tier primitives** — Motion, UI, and Catalog as distinct layers of abstraction
- **Multi-primitive support** — components ported across Radix UI, Base UI, and Headless UI
- **Deeper motion system** — accessible defaults, reduced-motion support, and composable animation primitives

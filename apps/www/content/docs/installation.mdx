<Callout>
  **Note:** We use installation process as
  [shadcn/ui](https://ui.shadcn.com/docs/installation).
</Callout>

<Steps>
<Step>

### Initialize shadcn/ui

Run the `init` command to create a new project with shadcn/ui or setup an existing one.

<CodeTabs
  codes={{
    pnpm: `pnpm dlx shadcn@latest init`,
    npm: `npx shadcn@latest init`,
    yarn: `yarn shadcn@latest init`,
    bun: `bunx --bun shadcn@latest init`,
  }}
/>

</Step>
<Step>

### Add components

Run the `add` command. Once Sora UI is listed in the official shadcn registry
(upstream PR in progress), `@soralabs/...` should work without extra setup.

<CodeTabs
  codes={{
    pnpm: `pnpm dlx shadcn@latest add @soralabs/text-reveal-blur`,
    npm: `npx shadcn@latest add @soralabs/text-reveal-blur`,
    yarn: `npx shadcn@latest add @soralabs/text-reveal-blur`,
    bun: `bunx --bun shadcn@latest add @soralabs/text-reveal-blur`,
  }}
/>

<Callout type="warn">
  **Only if the CLI errors** — for example `unknown registry`, cannot resolve
  `@soralabs`, or fetch timeout — add the scope manually to `components.json`:

  ```json
  {
    "registries": {
      "@soralabs": "https://ui.soralabs.io.vn/r/{name}.json"
    }
  }
  ```

  For local registry testing (Sora UI repo with `bun dev` running), use this
  instead:

  ```json
  {
    "registries": {
      "@soralabs": "http://localhost:3000/r/{name}.json"
    }
  }
  ```

  Prefer the production URL when localhost is unavailable.

  List available items:

  ```bash
  bunx --bun shadcn@latest list https://ui.soralabs.io.vn/r/registry.json
  ```
</Callout>

</Step>
<Step>

### Import Components

Import the component to your project.

```tsx
import { BlurTextReveal } from '@/components/sora-ui/texts/text-reveal-blur';

export default function Home() {
  return <BlurTextReveal text="Hello World" />;
}
```

</Step>
</Steps>

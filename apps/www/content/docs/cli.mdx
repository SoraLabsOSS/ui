**[sora-cli](https://www.npmjs.com/package/@soralabs/cli)** is a standalone CLI for installing components from any [shadcn](https://ui.shadcn.com)-compatible registry into your project. It defaults to the Sora UI registry, so it skips the extra step of registering the `@soralabs` scope that the [shadcn CLI](/docs/installation) needs — but it also works against any other registry via `--registry <url>`.

<Callout>
  sora-cli is in early development — installation may fail in the current release. If something breaks, fall back to the [shadcn CLI](/docs/installation) install commands and [report an issue](https://github.com/SoraLabsOSS/cli/issues).
</Callout>

<Callout>
  You still need `shadcn@latest init` first — see [Installation](/docs/installation) — since that sets up Tailwind, CSS variables, and the `@/` import alias every component depends on.
</Callout>

## Commands

<CodeTabs
  codes={{
    pnpm: `pnpm dlx @soralabs/cli@latest add text-effect`,
    npm: `npx @soralabs/cli@latest add text-effect`,
    yarn: `npx @soralabs/cli@latest add text-effect`,
    bun: `bunx --bun @soralabs/cli@latest add text-effect`,
  }}
/>

```bash
# multiple components in one call
npx @soralabs/cli add text-effect draw-underline-link

# interactive picker — no component names, browse and multi-select
npx @soralabs/cli add

# list every component available in the registry
npx @soralabs/cli list

# compare installed files against the current registry version
npx @soralabs/cli diff text-effect

# diagnose common project setup issues
npx @soralabs/cli doctor
```

### `add`

Resolves the dependency tree for the requested component(s), writes files into your project, and installs npm dependencies with your detected package manager (bun/pnpm/yarn/npm).

`add` supports universal component specifiers:
- **Bare names**: searches the Sora UI registry first, then automatically falls back to shadcn/ui base components (`button`, `dialog`, `input`, etc.) if not found.
- **Direct URLs**: points straight to any remote registry JSON file.
- **Local files**: installs from a local schema JSON file (e.g. `./registry/card.json`).
- **GitHub references**: installs directly from a GitHub repository (`owner/repo/item` or `github:owner/repo#branch/item`).
- **Namespaces**: resolves `@scope/item` using custom registries defined in your `components.json`.

```bash
# install from Sora UI or shadcn/ui base (auto-fallback)
npx @soralabs/cli add text-effect button

# direct URL from any shadcn-compatible registry
npx @soralabs/cli add https://magicui.design/r/marquee.json

# local registry item
npx @soralabs/cli add ./registry/custom-button.json

# direct from GitHub
npx @soralabs/cli add shadcn-ui/ui/button
npx @soralabs/cli add github:owner/repo#main/component

# scoped namespace defined in components.json ("registries": { "@magicui": "https://magicui.design/r" })
npx @soralabs/cli add @magicui/marquee

# flags and customizations
npx @soralabs/cli add text-effect --path src/components/ui
npx @soralabs/cli add card --cwd packages/ui       # run as if started in packages/ui (monorepos)
npx @soralabs/cli add text-effect --force           # overwrite existing files without asking
npx @soralabs/cli add text-effect --yes              # skip the install confirmation, for scripts/CI
npx @soralabs/cli add text-effect --dry-run          # preview what would change, write nothing
npx @soralabs/cli add text-effect --silent            # only print summary lines, not per-file output
npx @soralabs/cli add text-effect --view              # print file contents instead of writing them
```

<Callout type="warn">
  `--yes` matters most when an agent or script runs the CLI non-interactively: without it, `add` prints a confirmation prompt and — since there's no TTY — silently exits successfully without installing anything. Pair with `--force` to also skip per-file overwrite prompts.
</Callout>

### `list`

Lists every component the target registry exposes. Add `--json` for machine-readable output (safe to pipe — errors and status messages go to stderr, never mixed into the JSON on stdout).

```bash
npx @soralabs/cli list
npx @soralabs/cli list --json
```

### `diff`

Read-only comparison of installed component files against the current registry content — reports drift without writing anything.

```bash
npx @soralabs/cli diff text-effect
```

If files differ, re-run `add <component> --force --yes` to apply the update.

### `doctor`

Diagnoses common project setup issues before you install anything: Node version, package manager/lockfile conflicts, `components.json` validity, path alias configuration, Tailwind/React versions, `cn()` util dependencies, registry reachability, and whether a newer `sora-cli` version is available.

```bash
npx @soralabs/cli doctor
npx @soralabs/cli doctor --json
```

## Options reference

| Flag | Description |
| --- | --- |
| `--cwd, -c <path>` | Run as if started in `<path>` — for monorepos, e.g. `packages/ui`. Picks up that workspace's own `tsconfig.json`/`components.json` aliases. |
| `--path <path>` | Custom component install path. Only changes where files are written, without affecting which config gets detected (unlike `--cwd`). |
| `--registry <name\|url>` | Product registry key (default: `ui`) or a full registry URL. Must be HTTPS unless targeting `localhost`/`127.0.0.1`. |
| `--force` | Overwrite existing files without asking. |
| `--yes, -y` | Skip the install confirmation prompt — for scripts/CI. |
| `--dry-run` | Preview changes without writing files or installing packages. |
| `--silent, -s` | Suppress per-file output, keep summary lines. |
| `--view` | Print resolved file contents instead of writing them. |
| `--json` | Output as JSON (`list`, `doctor`). |
| `--version, -v` | Show the CLI version. |
| `--help, -h` | Show the help message. |

### Environment

`SORA_NO_UPDATE_CHECK` — set to disable the npm update check that runs on every invocation (printed to stderr, never mixed into `--json` output). Useful in CI.

## How it works

The CLI resolves component dependencies across multiple origins, writes files into your project with your configured path aliases, and installs npm dependencies with your detected package manager.

- **Universal Addressing**: When an address is provided, the CLI automatically detects whether it is a direct HTTPS URL, local file path, GitHub repository reference, or a scoped namespace from `components.json.registries`.
- **Shadcn Base Fallback**: For bare component names (e.g. `button`), `sora-cli` checks the primary registry first. If the item returns 404, it seamlessly falls back to `https://ui.shadcn.com` using the style configured in your `components.json`.
- **Cross-Registry Dependencies**: If a component from an external registry or URL depends on base primitives (like `button` or `utils`), the CLI traverses and flattens the dependency tree, placing base components into `components/ui` and rewriting import aliases so everything resolves out of the box.

Since components are copied into your project rather than installed as a package, `diff` is the way to check whether the registry has changed a component since you installed it, and `add <component> --force --yes` is how you apply that update.

Registry content isn't cryptographically signed, so only point `--registry` or custom URLs at sources you trust — files are written into your project and their dependencies are fed straight into your package manager.

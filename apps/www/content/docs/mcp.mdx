The **Sora UI docs MCP** server gives AI assistants live access to this site — installation guides, primitives, and the component catalog. It runs as a remote HTTP server at <code>{SORA_UI_MCP_URL}</code> (no local CLI required).

## Tools

| Tool | Description |
| --- | --- |
| `search_docs` | Search docs and components by keyword or phrase. Capped at 25 results per call — the response notes when results may be truncated, so narrow the query or raise `limit` |
| `get_page` | Fetch a page as markdown by slug (e.g. `primitives/accordion`, `primitives/draw-underline-link`) |
| `list_sections` | Browse the doc structure. Valid `section` filters: `documentation`, `components` |
| `get_component_info` | Without a `name`, lists installable Sora UI components and hooks with short descriptions. With a `name`, returns install guidance (the `sora-cli add`/`diff` commands to run), dependencies, and file targets — add `includeSource: true` to also get the full source (usually unnecessary, since installing already puts the real file on disk) |

<Callout>
  `get_component_info` lets you browse, inspect, and pull the source of a component directly from **Sora UI docs MCP** — its output points the agent at the [`sora-cli`](https://www.npmjs.com/package/@soralabsoss/sora-cli) command to actually run for a correct install (right import aliases, dependencies installed), so most agents can install straight from this one server. If you'd rather the agent install `@soralabs/*` via a dedicated MCP tool call instead of running a shell command, configure the [shadcn MCP server](https://ui.shadcn.com/docs/mcp) alongside it (see [Registry MCP (shadcn)](#registry-mcp-shadcn) below).
</Callout>

## How it works in practice

**MCP does not auto-suggest Sora components in the editor** — there is no autocomplete, component picker, or inline hint while you type JSX. MCP is **optional tooling for the AI agent**: after you enable a server, the agent *can* call its tools when your prompt is relevant, but it is neither always-on nor guaranteed on every message.

### Two servers, two jobs

| Server | Role |
| --- | --- |
| **`sora-ui`** | Read docs and browse the catalog — `search_docs`, `get_page`, `list_sections`, `get_component_info` (also returns a `sora-cli` install command) |
| **`shadcn`** | Install `@soralabs/*` into your project via the shadcn CLI, as an agent-callable tool instead of a shell command |

Use **both** if you'd rather the agent call an MCP tool to install than run `sora-cli`/`shadcn` itself — register `@soralabs` in `components.json` first, see [Installation](/docs/installation). Most agents with shell access can just run the command `get_component_info` returns.

### What is automatic vs manual

1. **Setup (manual, one-time)** — Add MCP config (or click **Add to Cursor** below), then enable the server under **Settings → Tools & MCP**. Restart Cursor if tools do not appear.

2. **During Agent chat (semi-automatic)** — The agent may call MCP when it decides it needs live docs — for example, you ask for a scroll-pinned hero and it searches for `scroll-gallery`. This depends on your prompt, mode (Agent vs Ask), and model; **it will not happen on every request**.

3. **Explicit prompts (most reliable)** — Name Sora UI or the task directly: *“List installable Sora UI components”*, *“Get install info for scroll-gallery”*, *“Get the source code for scroll-gallery”*, *“Add scroll-gallery from @soralabs and use variant=studio”*.

### What MCP is not

- **Not** IDE IntelliSense or Copilot-style inline completions
- **Not** a replacement for reading source when you already have components in your repo
- **Not** the same as project rules or skills — those load into context; MCP tools are invoked on demand

### Typical workflow

```text
1. Enable sora-ui MCP (+ shadcn MCP too, only if you want tool-call installs)
2. In Agent chat, ask naturally or explicitly:
   - "What Sora component fits a pinned scroll text reveal?"
   - "Install scroll-gallery and show usage with variant=studio"
3. Agent calls sora-ui MCP → reads docs / gets component info → runs
   `npx @soralabsoss/sora-cli add scroll-gallery --yes` (or `shadcn add`, if
   configured) → writes code in your repo
```

<Callout type="warn">
  The `--yes` flag matters when an agent runs `sora-cli` itself: without it, `add` prints a confirmation prompt and — since the agent's shell has no TTY — silently exits successfully without installing anything. `get_component_info` always includes `--yes` in the command it returns.
</Callout>

## Manual configuration (Cursor)

Add this to `.cursor/mcp.json` in your project (or `~/.cursor/mcp.json` for all projects):

```json
{
  "mcpServers": {
    "sora-ui": {
      "url": "https://mcp.soralabs.io.vn"
    }
  }
}
```

After saving, enable the server in **Settings → Tools & MCP** and restart Cursor.

## Add to Claude Code

[Claude Code](https://claude.ai/code) is Anthropic's official CLI. Add the server with one command:

```bash
claude mcp add --transport http sora-ui https://mcp.soralabs.io.vn
```

<Steps>
<Step>

Run the command above in your terminal (inside or outside a project).

</Step>
<Step>

Verify the server was added with `claude mcp list` — you should see **sora-ui** in the list.

</Step>
<Step>

Start a new Claude Code session and try a prompt like *"Search Sora UI docs for accordion"*.

</Step>
</Steps>

```json
  }
}
```

## Troubleshooting

### Agent does not use MCP tools

MCP is agent-driven, not automatic. Confirm the server is **enabled** (green) in **Settings → Tools & MCP**, use **Agent** mode (not Ask), and mention Sora UI explicitly in your prompt. Prompts like *“Search Sora UI docs for …”* or *“List installable Sora UI components”* are the most reliable way to trigger tool calls.

### Server not connecting

**Cursor**: Confirm **{SORA_UI_MCP_SERVER_NAME}** is enabled in **Settings → Tools & MCP**, restart Cursor after changing `.cursor/mcp.json`, and check **View → Output → MCP** for errors.

**Claude Code**: Run `claude mcp list` to verify the server is registered. If missing, re-run `claude mcp add --transport http sora-ui https://mcp.soralabs.io.vn`. Use `claude mcp get sora-ui` to inspect the saved config.

**Claude Desktop**: Confirm the JSON in `claude_desktop_config.json` is valid (no trailing commas), then fully quit and reopen the app.

### Tools return no results

- Use `list_sections` first to see available `documentation` and `components` sections
- For component pages, try slugs like `text-effect` or paths like `primitives/accordion`

### Install link does nothing

Paste the deeplink into your browser address bar, or add the [manual JSON config](#manual-configuration-cursor) above. See [Cursor MCP install links](https://cursor.com/docs/mcp/install-links).

### Nested `sora-ui` key in `mcp.json`

If Cursor shows *must have either a command or url* and your config looks like `"sora-ui": { "sora-ui": { "url": "..." } }`, remove the extra nesting — use the [manual JSON](#manual-configuration-cursor) shape, or click **Add to Cursor** again on this page (the install link encodes only `{ "url": "..." }`; the `name` query param supplies the server key).
